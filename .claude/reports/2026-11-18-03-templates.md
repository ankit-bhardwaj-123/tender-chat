# Feature check: 03 Templates (2026-11-18)

## Verdict

❌ Needs fixes. Almost all of it is solid and companies still work. But the View route's `Content-Security-Policy: sandbox` never gets to the browser: the global CSP in `next.config.ts` replaces it. So a `<script>` inside an uploaded template runs on our origin as the signed-in user. The fix is one header entry in `next.config.ts`.

## Bugs (code is wrong)

1. **High: the sandbox header on View is dropped, so stored XSS is possible.** `next.config.ts:364` together with `src/app/api/templates/[id]/file/route.ts:16`.
   - **What happens:** `next.config.ts` sets a CSP on `/(.*)`, and Next sets it on the response before the route handler runs. When Next copies the route's own headers, it skips any header that is already there (`node_modules/next/dist/server/send-response.js`, "only append the header if it is … not present"). So the browser gets the app CSP (`script-src 'self' 'unsafe-inline'`) instead of `sandbox`, and inline scripts in the template run as the user. I reproduced this with Next's own `sendResponse`: the route sent `sandbox` and the browser received the app CSP. The integration test passes only because it calls the handler directly, without Next's header step. Templates are files people send each other, so a shared "layout" could read or delete all of a user's tenders through `/api/*`.
   - **Reproduce:** upload `<p>{{x}}</p><script>alert(document.cookie.length)</script>`, then click View.
   - **Fix:** in `next.config.ts` `headers()`, add a second entry after the global one. Later entries overwrite earlier ones (`resolve-routes.js:561`):
     ```ts
     { source: "/api/templates/:id/file", headers: [{ key: "Content-Security-Policy", value: "sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:" }] }
     ```
     `default-src 'none'` also stops tracking pixels and outside fonts loading from user HTML. Loosen `img-src` if layouts need outside images. After the fix, check with `curl -I` on the deployed app as well, because Vercel applies config headers itself.
2. **Low: a stored-key upload ignores its kind.** `src/services/upload.service.ts:80-90`.
   - **What happens:** in the Blob path, `receiveUpload` checks the key's user but not its extension against `kind`. A `companyFile` blob (`.pdf` key, uploaded under the 10 MB token) can be registered as a template if it is ≤ 2 MB of UTF-8 and the name the client sends ends in `.html`. The plan says `receiveUpload` takes the kind. Harm is small (the content checks still run), but the kinds can mix.
   - **Reproduce:** `template-edges.test.ts` › "refuses a stored key that was not uploaded as an HTML file".
   - **Fix:** after the `KEY_PATTERN` match, also require `UPLOAD_LIMITS[kind].extensions.includes(match[2])`, otherwise `invalid("Upload the file first.")`.
3. **Low: placeholder names aren't NFC-normalized.** `src/shared/placeholders.ts:6`.
   - **What happens:** `{{क़ीमत}}` typed with the single code point U+0958 and the same word typed as क + ़ look identical but show as two placeholders. In Round 5 they would become two boxes, and a saved value might not match. Template names are already NFC (`template-body.ts:8`).
   - **Fix:** `(match[1] ?? "").normalize("NFC").replace(/\s+/g, " ").trim()`. Round 5's fill code must normalize the same way.
4. **Low: a network failure on edit or delete shows the raw browser text.** `src/lib/templates.ts:64-69,80`.
   - **What happens:** plain `fetch` throws a `TypeError`, so the toast says "Failed to fetch" instead of the spec's "Something went wrong, please try again." Upload paths already map failures to 502, which becomes the friendly message.
   - **Fix:** `fetch(...).catch(() => { throw new Error(FAILED); })` in `editTemplate` and `deleteTemplate`.
5. **Low (production only): over-2 MB uploads on Blob show the generic message.** `src/lib/file-upload.ts:71-72`.
   - **What happens:** Blob refuses the file at the token's 2 MB limit, and `sendToBlob` turns every Blob error into 502. The user sees "Something went wrong…" instead of "An HTML layout must be at most 2 MB." Companies have the same gap at 10 MB. I couldn't test this locally.
   - **Fix:** check `file.size` against the kind's limit before `upload()` and show the spec message (one shared limit table for client and server).

## Security

- **High:** bug 1 (sandbox CSP dropped) at `next.config.ts:364`.
- **Low:** bug 2 (kind not enforced on stored keys) at `upload.service.ts:80`.
- **Low:** there is no cap on how many templates a user can have (`template.service.ts:89`), the same as companies. Consider a limit later.
- **Low:** the local form path saves the whole upload before the size check (`upload.service.ts:74-77`), so a huge body is written and then deleted. On Vercel the 4.5 MB body limit caps this. It's the same as companies.

Checked and safe: 401 on every template route, 404 (never 403) for foreign, void and malformed ids on all six handlers, every query filtered by user and active, zod bodies with bad bodies answering 400, server-built `uploads/<userId>/<uuid>.<ext>` keys with no traversal, private Blob, unknown upload kinds refused at the token route, file names cleaned, UTF-8 checked with a fatal decoder, a failed create or replace discards the upload, old files deleted after a replace inside a row lock, errors are `{ error: { message } }` with no stack, no secrets in `NEXT_PUBLIC_*`, and React renders names and placeholders as text.

## Plan match

Matches the plan. Every file in the Files table exists, and the routes, methods, bodies and status codes match. The migration has only the two enums, the table, the foreign key and the index. ## Doing well

- The cleanup paths are careful. A failed create or replace discards the upload, the replace runs under a row lock and deletes the old file only after commit, and `discardUpload` never deletes a key that is in use.
- The upload kinds are a clean, table-driven change (`UPLOAD_LIMITS`). Companies kept their 10 MB pdf/jpg behaviour, and unknown kinds are refused at the Blob token.
- The existing tests are thorough: the four error messages, the exact 2 MB limit, the old file kept after a refused replace, and isolation on every route.
