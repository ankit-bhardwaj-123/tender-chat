## Bugs (code is wrong)
1. **Low: two first uploads at once leave an orphaned file.** The problem is in `src/services/company.service.ts:142-159`.
   - **What happens:** `lockCompanyFile` (line 146) can only lock a row that already exists. When two PUTs for the same company and kind arrive together with no file saved yet, both read `previous = null`. The second upsert then overwrites the first, and nobody deletes the first stored file.
   - **How to reproduce:** `tests/integration/company-edges.test.ts` "keeps exactly one stored file when two first uploads of the same kind arrive together". It finds 2 stored files where 1 is expected. In the browser this happens with two tabs, or with a retry while a slow upload is still running.
   - **Fix:** lock the company row first, so uploads to one company run one after another. Add a repo function such as `lockCompany(userId, companyId, tx)` that runs `select … from company where id and user_id and status='active' for update`, and use it in place of `findCompanyById(..., tx)` at line 143. The second upload then sees the first upload's row as `previous` and deletes its file.

## Security
- **Medium (UX of a security limit): Blob refusals show the generic message.** The code is at `src/lib/file-upload.ts:66-68` and `src/lib/companies.ts:14`. In production, Blob itself refuses a file over 10 MB (the token's `maximumSizeInBytes`). It probably also refuses a type it doesn't allow, such as a `.png` seal. `sendToBlob` catches that error and returns a 502, and `failure()` turns any status of 500 or above into "Something went wrong, please try again.". The owner wants "A file must be at most 10 MB." there. Pick one of these fixes:
  - In `uploadCompanyFile` (`src/lib/companies.ts:43`), throw "A file must be at most 10 MB." before sending when `file.size > 10 * 1024 * 1024`.
  - Or map `BlobFileTooLargeError` / `BlobContentTypeNotAllowedError` in the catch.

  This path can't run locally, so try it once on the deployed app.
- **Low: the whole file is accepted before the size check.** See `src/services/upload.service.ts:47-50` and `src/services/company.service.ts:69`. On the form path, `request.formData()` buffers the whole body in memory, and the whole file is written to storage before the 10 MB check runs. Locally there is no cap at all. On Vercel the 4.5 MB platform limit protects you. **Fix:** in the route, check `request.headers.get("content-length")` before you read the form, and answer 400 "A file must be at most 10 MB." when it is over about 10 MB plus the form overhead.
- **Low: bidi characters stay in file names.** `cleanFileName` (`src/services/company.service.ts:59`) strips `\p{Cc}` but not bidi controls such as U+202E. A name can then display as `gpj.exe`. The file is still served with a fixed content type, so the only risk is spoofing what the user sees. **Fix:** strip `[\p{Cc}\p{Cf}/\\]`.

## Quality and owner's rules

The own-file import chain `page.tsx → company-list.tsx → company-dialog.tsx → lib/companies.ts → lib/file-upload.ts` is 5 files deep. The rules are ≤ 3 for both. **Fix:** fold `CompanyForm` into `CompanyDialog`; the `key` on `CompanyDialog` already resets the form. For the import chain, decide whether `lib/file-upload.ts` counts as a shared leaf.

  - `pathOf` / `LocalFileStorage` (`local-storage.ts:10-12,72-74`).

  - The `fields` and `onProgress` parameters of `sendWithFiles`, which are never passed (`file-upload.ts:105-111`).

- **Copy-pasted logic.** The extension list and key builder appear in both `src/lib/file-upload.ts:11,33-38` and `src/services/upload.service.ts:21,25-33`. **Fix:** move them into one pure `src/shared/upload-key.ts`; `crypto.randomUUID` works on both sides.
