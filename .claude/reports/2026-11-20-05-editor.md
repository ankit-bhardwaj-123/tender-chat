# Feature check: 05 Editor (2026-11-20)

## Verdict

⚠️ Ready after small fixes. The backend is solid: every PATCH id is checked against the signed-in user's active rows, another user's tender, company or template answers 404, and a rejected PATCH writes nothing. The template iframe is sandboxed so scripts can't run. The issues are on the screen side. The page count never goes down while typing, the leave guard misses "New tender" and Back, the font override loses to a template's `!important`, and the script stripper eats ordinary text such as "one = Rs 500".

## Bugs (code is wrong)

1. **Medium: the page count only grows.** `src/components/editor/page-preview.tsx:140` measures `page.documentElement.scrollHeight`. For the root element of the iframe, that value is never smaller than the iframe's own height, and the iframe is `sheetHeight` tall (`:252`). So once a long value pushes the sheet to 2 pages, deleting the text leaves an empty page 2 (and "2 pages" in the header) until the font or template changes. **Repro:** paste a long text into a blank until page 2 shows, then clear it. **Fix:** measure the content, not the viewport: `page.documentElement.offsetHeight` (the `html` box, which already has `min-height: 297mm`) or `page.body.scrollHeight`.
2. **Medium: the leave guard misses "New tender" and Back.** The guard in `src/components/editor/editor-page.tsx:73-87` only catches `beforeunload` and clicks on `<a href>`. "New tender" navigates with `router.push` (`src/components/shell/new-tender-dialog.tsx:65`), and the browser Back button fires `popstate`. In both cases typed values are lost without the "Leave without saving?" question the spec asks for. **Fix:** in the New tender dialog, ask `window.confirm` before `router.push` when the editor is dirty. A small shared "dirty" store (`useSyncExternalStore`, like the zoom store) would let the shell read it. For Back, either accept it (and say so in the spec) or push a guard history entry.
3. **Low: `stripScripts` removes ordinary text.** At `src/shared/fill-template.ts:25` the `on…=` pattern runs over the whole document, not just inside tags. "Rate for one = Rs 500" becomes "Rate for 500", and "Paid once = 5 times" becomes "Paid times". This is likely in English templates. The test `fill-template-edges.test.ts` "keeps body text that only looks like an event handler" fails on it. **Fix:** strip only inside tags: `html.replace(/<[^>]+>/g, (tag) => tag.replace(/\son[a-z]+\s*=\s*(...)/gi, ""))`. The sandbox is the real guard anyway.
4. **Low: a `>` inside an attribute breaks the "inside a tag" check.** At `src/shared/fill-template.ts:67`, `<a title="a>b {{x}}">` is treated as body text, so a `<span data-field="x">` is pushed into the attribute. Its quotes then end the attribute early and garble the markup. The test "does not put a span inside an attribute whose value holds a >" fails on it. It's rare, so it's a low priority. **Fix:** walk tags with a small scanner that skips quoted attribute values, or match blanks inside `<[^>]*>` with a quote-aware tag regex first.
5. **Low: the font override can lose to the template.** `fontOverrideCss` (`src/shared/fill-template.ts:50-52`) emits `html,body,body *{font-family:… !important}` as the first thing in `<head>`. The selector `body *` is as weak as `p`, so a template rule `p{font-family:Arial !important}` (later in the file, same weight) wins. `.title{… !important}` or an inline `style="font-family:… !important"` also win. The spec says "the dropdown always decides the font". **Fix:** inject the override as the last thing before `</head>` (or at the end of `<body>`), and raise its weight, for example `:root body, :root body *:not(#\#)`. Optionally also drop `font-family` from inline `style` attributes.
6. **Low: `updatedAt` mixes two clocks.** `src/repositories/tender.repository.ts:75` sets `new Date()` (app clock), while inserts use the database's `defaultNow()`. In the test run, the app clock was about 0.7 s behind Neon, so a PATCH right after create stored an `updatedAt` earlier than the create time. The sidebar sorts by `updatedAt`, so a just-edited tender can sort wrongly. **Fix:** `updatedAt: sql\`now()\`` in the repository.

## Security

None found at high or medium severity.

- **Low: Save errors show the server's message.** `src/lib/editor.ts:66` passes on a 4xx message ("Tender not found.", "The request body is not valid."), while the spec's table says Save fails with "Something went wrong, please try again.". It's safe (no internals), just different. **Fix:** use the fixed message for Save, or keep it and update the spec.
- **Low: no size cap on `values`.** Route handlers have no body limit locally (Vercel caps at 4.5 MB). A user can only bloat their own row, so this is acceptable. The plan already accepted it.

Checked and safe:

- **Auth and ownership:** GET and PATCH need a session (401). The tender, company and template are all looked up with the user id and `status = active` (`tender.service.ts:72-87`), and every other-user, void or missing id answers the same 404 body.
- **Rejected writes:** a rejected PATCH writes nothing, because the checks run before the update.
- **Input:** `parseId` covers the URL id and zod covers the body. Unknown fields (`userId`, `type`, `id`) are dropped. No raw SQL.
- **Template iframe:** `sandbox="allow-same-origin"` with no `allow-scripts`, so scripts, forms, popups, top navigation and meta refresh are blocked. The `srcdoc` frame also inherits the app CSP (`img-src 'self' blob: data:`, `connect-src` limited), so a template's `<img src="https://…">` can't call out.
- **Escaping:** values reach the DOM only through `escapeHtml`/`valueHtml` (`page-preview.tsx:60`). There's no `dangerouslySetInnerHTML`.
- **Fonts and letterhead:** font CSS is built only from the fixed list. Letterhead and seal come from our own owner-checked routes.
- **No secrets** in this feature.

## Quality and owner's rules

- **setState in an effect:** `src/components/editor/page-preview.tsx:143` runs `useEffect(refresh)` after every render, and `refresh` calls `setSealTop`/`setContentHeight` (`:139-140`). Lint misses it because the call is indirect, but it breaks the owner's rule. It also walks every text node on each keystroke. **Fix:** keep the DOM patching (no state) in the effect, and do the measuring in a `ResizeObserver` on the iframe's `body`, set up in `onFrameLoad`. Setting state in an observer callback is allowed, and it fixes bug 1 at the same time.
- **Seal flash:** right after a font or template change, `refresh` runs on the new, still blank iframe and puts the seal near the top until `onLoad`. The `ResizeObserver` change above removes this too.
- **Import chain depth:** `page.tsx → editor-page.tsx → page-preview.tsx → lib/editor.ts → shared/fill-template.ts → shared/placeholders.ts` is 6 own files, against a limit of ≤ 3. This is the same open question as the 02 report: decide whether `src/shared/*` counts as leaves. Component depth (`EditorPage → PagePreview → LetterheadPage`) is fine.
- **Hex values:** `src/lib/editor.ts:35` uses `#eeeeea`/`#565c66` in the iframe CSS. Theme classes can't reach inside the iframe, so this is fine. Optionally name them `MUTED`/`MUTED_FOREGROUND` with a matching note in the `frontend-ui` skill.
- **Double status:** `src/components/editor/editor-page.tsx:232-233` uses `Spinner` (which already has `role="status"`) with `aria-hidden` next to a `span role="status"`. It works, but drop one of them.
- **`lang="hi"` always:** `src/components/editor/placeholder-form.tsx:31,36` sets `lang="hi"` even for an English template (`template.language`). **Fix:** pass the template language down.
- **CHANGELOG:** add a line for the three new test files from this check.
- **Style:** no comments, no classes, plain interfaces, and route → service → repository is respected. No dead code or unused imports found.

## Plan match

Matches the plan, with these differences:

- **Draft key:** the draft is keyed by `tenderId:templateId`, not `updatedAt`. That's better, because a company change no longer wipes typing. Update the plan line.
- **Seal position:** the seal sits 2 lines below the last text, not at a fixed bottom-right spot. This was agreed later (CHANGELOG "Changed"), but the spec still says "fixed spot (bottom right)". Update the spec.
- **PagePreview props:** it takes an extra `hasTemplate` prop. Fine.
- **Leave guard:** only partial (bug 2). The plan flagged this as a risk.

## Doing well

- `checkedChanges` (`src/services/tender.service.ts:64-90`) checks every id before any write. A mixed bad PATCH leaves the row exactly as it was, and the tests prove it.
- The live preview patches only the `[data-field]` spans while typing (`page-preview.tsx:49-64`), using the same escaping as the server. The iframe isn't rebuilt on each key, so typing stays smooth.
- Clean SSR handling: `useSyncExternalStore` for zoom and media query, plus a do-nothing split storage, so there are no hydration effects.
