## Tests written

- `tests/unit/font-faces.test.ts` (new, 6 tests)
  - `FontFaces` renders exactly one `<style>`.
  - React's server render keeps the CSS quotes intact, with no `&quot;`, so the `@font-face` rules really work.
  - All 34 `url()`s point to `/fonts/<file>.woff2`, with no `http(s):`, `googleapis` or `gstatic`.
  - Every one of the 10 families has a face.
  - `companySummary` gives "Letterhead · Seal · Mukta" and "No files yet · Poppins (default)".
- `tests/integration/company-fonts.test.ts` (new, 11 tests)
  - The created font is stored in the database and shows in the list GET.
  - A row inserted without `font_key` (a company made before this feature) reads as `null`.
  - A PATCH with an unknown, empty, wrongly cased, numeric or `../` font answers 400 and changes neither name nor font. A POST with `""`, `"Mukta"` or `" mukta"` answers 400.
  - A PATCH with only a name keeps the font in the database (Round 5 relies on this), and a PATCH with `null` clears it.
  - Another user gets 404 on GET, and the 404 body doesn't leak the font. Another user's PATCH with `null` answers 404 and the font stays.
  - Setting a font on a deleted company or a missing id answers 404. A signed-out PATCH answers 401, and the font stays.

## Security

- **Low: 400 message differs from the plan.** In `src/shared/company-body.ts:11-15`, an unknown font answers "The request body is not valid." instead of "Unknown font.". The cause is that `readJson` (`src/server/http.ts:37-39`) drops zod messages. This is safe; it's only less helpful. The owner already knows. If wanted, have `readJson` pass on the first issue's message when one is set, and give the refine a message: `.refine(isFontKey, { message: "Unknown font." })`.

Checked and safe:

- **Auth and ownership:** every route still needs a session. Ownership goes through `activeCompanyOf(userId)` in the update `WHERE`, so other users and deleted rows get 404 and nothing changes.
- **Input:** the font key must be one of 10 fixed keys, and a stored key is checked again on read (`dto.ts`).
- **CSS:** the `@font-face` CSS and the `fontFamily` style are built only from constants, never from user text.
- **No outside requests:** no external font hosts in `src/` or `next.config.ts`. The CSP (`font-src 'self' data:`, `style-src 'self' 'unsafe-inline'`) already allows these files and was not weakened.
- **No secrets:** none added or exposed.

## Quality and owner's rules

- **Low: Hindi sample has no language tag.** `src/components/companies/font-field.tsx:47` shows the "नमस्ते निविदा" sample without `lang="hi"`. Screen readers will read it with an English voice. **Fix:** `<span lang="hi" className="text-muted-foreground">{SAMPLE}</span>`.
- **Low: CHANGELOG doesn't list the new test files.** **Fix:** add one line under Added for `tests/unit/font-faces.test.ts` and `tests/integration/company-fonts.test.ts` (from this check). There is also a stray blank line between the Spec 04 entries and the "Font plan changed" entry in `CHANGELOG.md`.
- **Depth (older issue):** `FontField` sits at the same 4th component level as `FileField` (`CompanyList → CompanyDialog → CompanyForm → FontField`). This is the depth issue already raised in the 02 report, not new here.
- **Style:** no comments, no classes, plain interfaces, theme tokens only (`text-muted-foreground`), and the label is tied to the trigger (`htmlFor="company-font"`). No dead code or unused imports.

## Plan match

Matches the plan, with one agreed difference: the 400 message (see Security).

- Every file in the Files table exists. `updateCompanyName` was renamed to `updateCompany` and `saveCompanyName` to `saveCompany`, as planned.
- The flow is route → service → repository.
- The migration adds only one column that can be empty.
- The script copies 34 files, with weights `[400]` for Tiro Devanagari Hindi, Yatra One and Gotu.

## Doing well

- The font list is checked twice: on write by the zod body, and on read in `toCompany`. Removing a font later needs no migration and can't break old rows.
- `fontFaceCss` builds one rule per font, weight and subset using Fontsource's own `unicode-range`. The browser only downloads the subset that text on screen needs, and the unit test checks that every named file exists.
- The repository's "fontKey left out isn't written" rule (`company.repository.ts:91`) is small and explicit. It gives Round 5 exactly the PATCH behaviour it needs.
